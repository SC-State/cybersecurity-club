Full walkthrough

Build your home lab

The home lab is the one setup half the bank depends on — and it's the step that trips people up most. This is the never-done-this-before version: every click, every fiddly bit, and the fixes for what usually goes wrong. Do it once and reuse it all year.

⏱ Give yourself an afternoon the first time. ☕ You'll download a few GB, so get on good Wi-Fi.

First, the idea

What you're building

A virtual machine (VM) is a whole second computer running inside a window on your real one. You can install an operating system in it, break things, even get it infected — and your actual laptop is never touched. Delete the VM and make a new one anytime.

Your lab is two VMs on a private network: Kali Linux (the attacker machine, loaded with security tools) and a deliberately-weak target machine to practice on. They can talk to each other but not to the internet or your real network — so nothing you do can escape or cause real harm.

The free program that runs VMs is VirtualBox. That's what you install first.
The five parts
  1. Install VirtualBox
  2. Add Kali Linux (the attacker)
  3. Add a target machine
  4. Put them on a private network
  5. Boot both and confirm they can see each other
Part 1

Install VirtualBox

  1. Download it.

    Go to virtualbox.org → Downloads, and pick your system: Windows hosts, macOS / Intel hosts, or Linux. Run the installer and accept the defaults. On Windows, click Yes / Install if it warns about installing a network driver — it needs that.

  2. Add the Extension Pack.

    On the same download page, download the VirtualBox Extension Pack (one file for all systems). Then in VirtualBox open File → Tools → Extension Pack Manager → Install, and pick the file you downloaded.

  3. Open it once to check.

    Launch VirtualBox — you should see the VirtualBox Manager with an empty list of machines on the left. That's success for Part 1.

Apple Silicon Mac (M1/M2/M3)? Regular VirtualBox doesn't run the standard Intel images well. Use UTM (free, from mac.getutm.app) with an ARM Kali image instead — and for your target, use a browser-based TryHackMe room rather than a local Intel VM. The rest of this guide's concepts still apply.
Part 2

Add Kali Linux — the attacker

Kali is a Linux system pre-loaded with security tools. You'll grab a ready-made VirtualBox image so you don't have to install an OS from scratch.

  1. Download the Kali VirtualBox image.

    Go to kali.org/get-kali → the Virtual Machines tab → the VirtualBox image (64-bit). This is a prebuilt VM, not an installer — it saves hours. It's a big file (a few GB), so let it finish.

  2. Extract the download.

    The file is a .7z archive — a compressed folder. You need a tool to unzip it: 7-Zip on Windows (free, 7-zip.org) or Keka on Mac (free, keka.io). Right-click the .7z file → Extract here / Extract to…. You'll get a folder with a few files inside, including one that ends in .vbox.

  3. Add it to VirtualBox.

    In VirtualBox, click Machine → Add, browse to the extracted folder, and select the .vbox file. Kali now appears in your machine list — you did not have to install anything.

    Note the login. Kali's default username and password are both kali. You'll need them when it boots.
Part 3

Add a target machine

You need something to practice on. The classic choice is Metasploitable 2 — a Linux machine built to be full of holes. (Prefer zero hassle? See the easy alternative at the end of this part.)

  1. Download Metasploitable 2.

    Get it from its official page, sourceforge.net/projects/metasploitable. It downloads as a .zip; extract it (right-click → Extract) and you'll find a disk file ending in .vmdk.

  2. Create a VM that uses that disk.

    In VirtualBox click New. Name it Metasploitable2, set Type Linux and Version Ubuntu (32-bit) — Metasploitable 2 is an old 32-bit system, so do not pick a 64-bit option or it may not boot. Click Next. Give it about 512 MB RAM. When it asks about a hard disk, choose “Use an existing virtual hard disk file,” click the folder icon → Add, and pick the .vmdk you extracted. Click Create.

    Note the login. Metasploitable's username and password are both msfadmin.
Easy alternative (no second VM): if the target is giving you trouble, use a free TryHackMe room in your browser instead — it gives you a target machine to attack without any local setup. Your Kali VM can still be the attacker for everything else in the bank.
Part 4

Put them on a private network

This is the safety step: a host-only network lets your two VMs talk to each other but not to the internet or your real Wi-Fi. Nothing you do can escape the lab.

  1. Create the private network.

    In VirtualBox: File → Tools → Network Manager → the Host-only Networks tab → Create. It makes a network, usually numbered 192.168.56.0/24. You only do this once.

  2. Attach each VM to it.

    For each VM (Kali and the target): select it, open Settings → Network → Adapter 1, set Attached to: Host-only Adapter, and in the Name dropdown pick the network you just created. Click OK. Do this for both machines so they're on the same network.

  3. (Optional) give Kali internet to update tools.

    If you want Kali to reach the internet (to update its tools), open its Settings → Network → Adapter 2, tick Enable Network Adapter, and set Attached to: NAT. Keep all your actual attacking on the host-only adapter. The target stays host-only only.

Part 5

Boot both and confirm they see each other

  1. Start both VMs.

    Select each one and click Start. A window opens and the machine boots. Log in with the credentials from earlier — Kali is kali/kali, the target is msfadmin/msfadmin.

  2. Find each machine's IP address.

    On Kali, open a terminal (the icon in the top bar) and run:

    ip a

    On the target, at its login prompt, run:

    ifconfig

    Look for an address that starts with 192.168.56. on each — that's its address on your private network. Write the target's down.

  3. Ping the target from Kali.

    Back on Kali, ping the target's address (replace it with the one you wrote down — the example below uses the usual Metasploitable address):

    ping -c 4 192.168.56.101

    Four replies = success. Your two machines can see each other, safely isolated. Press Ctrl+C to stop a ping that keeps going.

  4. Take a snapshot of each VM.

    Power a VM off, select it, open its Snapshots view (top right), and click Take. Name it clean install. A snapshot is a saved point in time — after any messy experiment, select it and click Restore to roll back in seconds.

    Snapshots are not backups — they live inside the same VM file. Keep the original Kali download too, just in case.
That's the lab. You now have an attacker, a target, and a safe sealed network — the foundation for most of the bank.

If something goes wrong

The VM won't start, or only 32-bit options show up

This is the most common one: virtualization (VT-x / AMD-V) is turned off in your computer's BIOS/UEFI. Restart, press the key that opens BIOS/UEFI during boot (often F2, F10, Del, or Esc — the screen usually says which), find a setting named Virtualization, VT-x, SVM, or AMD-V, enable it, save, and reboot.

On Windows, Hyper-V or "Core Isolation / Memory Integrity" can also block VirtualBox. If VMs still won't run 64-bit, search "turn Windows features on or off," and try turning off Hyper-V and Windows Hypervisor Platform, then restart.

The two VMs can't ping each other

Almost always the network adapters don't match. Check that both VMs have Adapter 1 set to Host-only Adapter on the same network name (Part 4, step 2). Both addresses should start with 192.168.56. — if one doesn't, fix its adapter and reboot that VM.

Also make sure you're pinging the address the target actually showed in ifconfig, not the example in this guide.

Kali has no internet (for updating tools)

Host-only on its own has no internet by design. Add a second adapter set to NAT (Part 4, step 3) and reboot Kali. Keep all attacking on the host-only adapter.

I'm on an Apple Silicon Mac (M1/M2/M3)

Standard VirtualBox and the Intel Kali/Metasploitable images don't run well on Apple Silicon. Use UTM (mac.getutm.app) with an ARM Kali image for your attacker, and use a browser-based TryHackMe room as your target instead of a local Intel VM. You still get a real lab, just assembled a bit differently.
