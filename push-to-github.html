Portfolio basics

Push your work to GitHub

You did the project — now get it onto your GitHub, where a recruiter can actually see it. Doing the work is step one; showing it is step two. Here are three ways to do it, from no-install-needed to real developer workflow. Any of them works. Pick one.

First time? You need a GitHub account and a repo. If you don't have them, do Create a GitHub account and Start a security portfolio in the bank first — they take a few minutes.

Start here

Path A — The website

No installing anything. You just drag your files into your repo in the browser.

  1. Open your repo on github.com.

    Go to github.com/your-username/your-repo — the repo you made in Start a security portfolio (for most people that's cybersecurity-projects).

  2. Click Add file → Upload files.

    It's a button near the top right of the file list.

  3. Drag your files into the box.

    Drop in your write-up (README.md) and any screenshots. To put them inside a folder, instead click Add file → Create new file and type the folder and file together, like home-lab/README.md — the slash makes the folder.

  4. Write a short message and commit.

    Scroll down, type something like "Add home lab write-up" in the box, leave "Commit directly to the main branch," and click Commit changes.

  5. Done — it's live.

    Refresh the page and your files are there, at github.com/your-username/your-repo. That link is what you paste in the GroupMe.

Images not showing in your README? The image file has to be in the same folder as the README.md, and you link it like ![scan results](screenshot.png) using the real file name.
Easy app

Path B — GitHub Desktop

A free app that does git with buttons — no commands, no passwords to fight with. Nice once you're uploading often.

  1. Install GitHub Desktop.

    Download it from desktop.github.com (Windows and macOS), install, and sign in with your GitHub account.

  2. Clone your repo.

    Go to File → Clone repository, pick your repo from the list, and choose a folder on your computer to keep it in.

  3. Add your files.

    Open that folder on your computer (the app shows a "Show in Finder / Explorer" button) and copy your write-up and screenshots into it. GitHub Desktop will notice the new files automatically.

  4. Commit and push.

    Back in the app, type a summary like "Add home lab write-up" at the bottom left, click Commit to main, then click Push origin at the top. That sends it to GitHub.

  5. Check it online.

    Open your repo on github.com and your files are there. Grab the link for the GroupMe.

Real git

Path C — Command line

The terminal way. Slightly more to learn, but using git is a genuine skill — and a line on your résumé on its own.

Where do these commands go? Into a terminal. On Windows press Start and type cmd to open Command Prompt (PowerShell works too); on Mac open Terminal (Applications → Utilities → Terminal); on Linux / Kali open the Terminal app. Type each line and press Enter.
  1. Install Git.

    Get it from git-scm.com (Windows). macOS and most Linux already have it — check with git --version. On Kali and Ubuntu: sudo apt install git.

  2. Tell git who you are (once). 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
  3. Clone your repo and go into it.

    Copy the HTTPS URL from the green Code button on your repo page, then:

    git clone https://github.com/your-username/your-repo.git
cd your-repo
  4. Add your files into that folder.

    Copy your write-up and screenshots into the cloned folder (make a subfolder like home-lab/ if you want).

  5. Stage, commit, and push. 
    git add .
git commit -m "Add home lab write-up"
git push
  6. Sign in when it asks.

    On your first push, git opens a browser window to sign in to GitHub — do that and it remembers you. (If it asks for a password in the terminal instead, GitHub no longer accepts your account password there; create a Personal Access Token under Settings → Developer settings → Personal access tokens and paste that as the password.)

If something goes wrong

"Authentication failed" or it keeps asking for a password

GitHub stopped accepting your account password for git in the terminal. Use a Personal Access Token instead: on github.com go to Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token, give it the repo scope, copy it, and paste it when git asks for your password.

Or skip all of that and use Path A (website) or Path B (GitHub Desktop) — neither one makes you deal with tokens.

My screenshot isn't showing in the README

The image file has to be uploaded into the same folder as the README.md that references it, and the link has to use the exact file name: ![alt text](screenshot.png). GitHub is case-sensitive, so Screenshot.PNG and screenshot.png are different files.

My README doesn't show up on the repo's front page

GitHub only auto-displays a file named exactly README.md (that capitalization). If yours is readme.txt or Readme.md, rename it to README.md.
